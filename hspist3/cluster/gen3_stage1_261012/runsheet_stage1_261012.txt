WHAT IT DOES. Each chunk is one array task of one core: it runs its task lines (consecutive lines of one (cell, mass)) one after the
other with s1_worker_koa.sh and the campaign binary ~/harddisks_gen3_s1/hspist3/00ALLINONE (00ALLINONE  git f72d764  target koa), checked at start
against the committed build record and the build-time record, without git. Chunk 1 runs alone first (G6 (e)); then the groups in
the registered order (sec. 4.8.8): B100, B400, D, B900, S, B1600. A group's arrays are one per time class (--time is the class), typed together;
their throttles add up to 64 at most, so at most 64 chunks run at once over all stage 1 arrays (sec. 4.8.8; 128 only with the plan
author's go on a pasted sinfo line with >= 10 % of the nodes idle). The next group's arrays are typed only after the previous group's
merge has ended. The merge (one per group) checks every chunk's log and folder, plans before it moves anything, reduces every
(cell, mass) and compresses the traces; the fetch brings the summaries, run records, logs, every snapshot and the whole (N 100, pi/8) cell.

"STOP: [<node>] ..." on a failed start-up check before it runs anything: paste the STOP line, change nothing, wait. NO GIT AT RUN
TIME; every sbatch file carries --exclude=cn-05-08-07. THE SANDBOX LINE is the established one: srun -p sandbox -t 1:00:00 -c 2 --mem=4G --pty /bin/bash
