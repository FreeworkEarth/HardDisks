Checking the Status of Jobs and the Cluster

Slurm provides several commands to help you see what the cluster is doing and to track the progress of your jobs.

squeue: Check the Job Queue

Use this command to see which jobs are currently running or waiting in the queue. It's the best way to check the status of your own jobs.

Common Usage Description
squeue Shows all jobs currently in the queue. Can be a very long list.
squeue --me (Most useful) Shows only your jobs.
squeue -j 12345 Shows the status of a specific job ID (e.g., 12345).

sinfo: Check the Cluster Status

Use this command to see the status of the compute nodes. This helps you see how busy the cluster is and what resources are available.

  • It shows which partitions (groups of nodes) are available.

  • It tells you if nodes are idle, alloc (allocated/busy), or down.

  • The output on Koa is customized to show details about GPUs and other specific hardware features.

sprio: Check Job Priority

Use this command to see the priority calculation for all pending jobs. This can help you understand why some jobs are scheduled before others.

  • Jobs with a higher number have a higher priority and are more likely to run next.

  • Your job's priority increases the longer it waits in the queue.

seff Command: Checking Your Job's Efficiency

The seff (Slurm efficiency) command is a simple but powerful tool that gives you a performance report on a completed job. It helps you answer the crucial question: "Did my job make good use of the resources I requested?"

Syntax:

seff <job_id>

Example:

[ ~]# seff 7888913
Job ID: 7888913
Cluster: mana
User/Group: user/user
State: COMPLETED (exit code 0)
Nodes: 1
Cores per node: 10
CPU Utilized: 00:00:10
CPU Efficiency: 11.11% of 00:01:30 core-walltime
Job Wall-clock time: 00:00:09
Memory Utilized: 975.45 MB
Memory Efficiency: 1.49% of 64.00 GB (64.00 GB/node)

What the Output Tells You

The seff command provides a clean summary with several key metrics:

  • Job Wall-clock time: The actual real-world time your job took to run from start to finish.

  • Total CPU time: The combined time all of your requested CPU cores spent actively working.

  • CPU Efficiency: This is the most important metric. It compares the actual CPU time used against the total CPU time you reserved. A low percentage means your job requested many more CPU cores than it could actually use, leaving them idle. Your goal is to get this as close to 100% as possible.

  • Memory Utilized: The peak amount of RAM your job used.

  • Memory Efficiency: Compares the peak RAM used against the amount you requested. A low percentage means you requested much more RAM than your job needed.

jobstats Command: Checking Your Job's Efficiency

The jobstats command is a powerful, detailed performance analysis tool developed at Princeton University. It goes much deeper than seff by providing time-series plots that show you how your job used resources throughout its entire runtime.

Think of it this way:

  • seff gives you the final score of a game (e.g., you used 50% of the CPU).

  • jobstats gives you the play-by-play analysis, showing you exactly when in the game your team was performing well or poorly.

This is extremely useful for understanding complex jobs with different stages, such as a data-loading phase followed by a computation phase.

How to Use jobstats

The jobstats command is a script that needs to be run after your job has completed. It processes the performance data collected by Slurm during the run.

Syntax:

jobstats <job_id>

Example:

jobstats vs. seff: Which One Should I Use?

seff jobstats
Purpose Quick, overall summary of job efficiency. Detailed, visual analysis of performance over time.
Output Simple text summary (CPU %, Memory %). HTML report with time-series graphs.
Best For Getting a fast, "at-a-glance" check on any completed job. Troubleshooting inefficient jobs, optimizing complex code, and understanding jobs with multiple stages.
When to Use Use it routinely on most of your completed jobs. Use it when seff reports low efficiency and you need to know why.
