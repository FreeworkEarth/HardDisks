Community Partitions on Koa

Any user on Koa can submit jobs to the community partitions. They are designed for different types of tasks, primarily separated by how long your job needs to run.

Short-Run Partitions

These partitions are designed for jobs with fast turnaround times. They are perfect for interactive tasks where you need resources quickly, such as:

  • Compiling code

  • Testing and debugging scripts

  • Development and optimization

Short-Run Partitions (sandbox & gpu-sandbox)

These partitions are designed for short, interactive jobs like compiling, testing, and debugging code. They provide rapid access to resources to help you prepare your main computational jobs.

Standard Partitions: For Production and Research Jobs

Standard Partitions

Use these partitions when your code is tested and ready to run for your research, or for any task that will take longer than four hours.

A job in these partitions will run until it is complete, or until it is terminated for one of the following reasons:

  • It runs out of the requested wall time.

  • It tries to use more memory than requested.

  • (GPU jobs only) It fails to use all the GPU resources it requested.

At-a-Glance Comparison

This table helps you quickly choose the best partition for your job.

Partition Name Best For (Use Case) How Resources are Allocated Max Job Time
shared Single-node, multi-threaded jobs. By the CPU core (share a node with others). 3 days
shared-long Long-running, single-node, multi-threaded jobs. By the CPU core (share a node with others). 7 days
exclusive Multi-node MPI jobs. By the whole node (you get the entire server). 3 days
exclusive-long Long-running, multi-node MPI jobs. By the whole node (you get the entire server). 7 days
gpu GPU-accelerated applications. By the CPU core and whole GPU. 3 days

Detailed Partition Information

shared & shared-long

These partitions allow your job to request a specific number of CPU cores and memory on a single server, which you may share with other users' jobs.

  • Best For:

    • Multi-threaded applications that run on a single machine.

    • Jobs that don't need all the CPU cores or memory on a full node.

exclusive & exclusive-long

These partitions allocate entire compute nodes exclusively to your job. No one else can run on the nodes you are assigned.

Best For:

    • Large-scale MPI (Message Passing Interface) jobs that need to communicate across multiple nodes.

    • Workloads that require all the resources on one or more nodes without interference.
