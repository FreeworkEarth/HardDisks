Understanding Job Types on Koa: Batch vs. Interactive

here are two fundamental ways to run work on the Koa cluster: Batch jobs and Interactive jobs. Choosing the right one depends on your task.

At-a-Glance Comparison

Feature Batch Job Interactive Job
Analogy Sending a detailed email with instructions. Making a live phone call.
Best For Production & Research: Running your main scientific computations. Preparation & Debugging: Compiling, testing, and troubleshooting code.
User Interaction None. You submit the job and wait for it to finish. Direct. You get a command prompt and type commands in real-time.
Typical Duration Can be very long (days or weeks). Relatively short (minutes to a few hours).

1. Batch Jobs

This is the standard and most common way to run jobs on Koa. A batch job runs independently in the background without any user interaction.

  • How it Works: You write all the commands you want to run into a shell script file. You then submit this script to the Slurm scheduler using the sbatch command. Slurm will run your job when resources become available and will email you when it's complete.

  • Best For:

    • Running scientific simulations or data analysis that takes hours or days.

    • Any task that can be fully automated in a script.

    • Submitting hundreds or thousands of similar tasks (job arrays).

2. Interactive Jobs

An interactive job gives you a live command-line prompt directly on a compute node. This allows you to type commands and see the results immediately, as if you were logged into a dedicated server.

  • How it Works: You request resources for a specific amount of time using the salloc command. Once the resources are granted, your terminal connects to a compute node where you can work in real-time. The session ends when you exit or your requested time runs out.

  • Best For:

    • Compiling software.

    • Debugging code that is crashing or giving strange results.

    • Testing scripts and workflows before submitting a large batch job.

    • Any task that requires direct human input.

Callout

Interactive Apps submitted via the web portal for Koa are in fact batch jobs.  What makes them interactive is the additional layer that the web portal provides.
