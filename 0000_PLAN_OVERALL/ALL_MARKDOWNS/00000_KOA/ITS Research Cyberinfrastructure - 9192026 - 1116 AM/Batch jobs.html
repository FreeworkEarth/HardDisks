How to Submit a Job on Koa

Once you have created your job script, you need to submit it to the Slurm scheduler. The scheduler will then run your job when the necessary resources become available.

The command to submit a batch job is sbatch.

Online documentation from SchedMD

Step 3: Review the Job Script (Optional)

You can view the contents of the script, non_mpi.slurm, to see the #SBATCH directives and the commands it will run.

Once in the examples directory, we can take a look at the job script if we desire using a command-line text editor such as emacs, vim, neovim, nano and make edits if we want. 

non_mpi.slurm


#!/bin/bash
#SBATCH --job-name=example
#SBATCH --partition=sandbox

#SBATCH --time=0-01:00:00 ## time format is DD-HH:MM:SS

#SBATCH --cpus-per-task=1
## max amount of CPU memory per node you require
#SBATCH --mem=6g 

#SBATCH --error=hello-%A.err ## %A - filled with jobid
#SBATCH --output=hello-%A.out ## %A - filled with jobid

##SBATCH --mail-type=BEGIN,END,FAIL,REQUEUE
##SBATCH --mail-user=user@test.org

## All options and environment variables found on schedMD site: http://slurm.schedmd.com/sbatch.html

### begin commands to run ###

module purge
module load toolchain/intel
make

./hello ${RANDOM}

Step 4: Submit the Job

Use the sbatch command to send the script to the scheduler.

Upon submission, Slurm will give you a unique Job ID (7534798 in the example below). This is how you will track your job.

What Happens After You Submit?

You can monitor your job's progress and see the final results once it's finished.

1. Check the Job Status

Use the squeue --me command to see the status of your jobs.

  • Your job will first appear with the status PD (Pending), meaning it is waiting for resources.

  • Once it starts, the status will change to R (Running).

  • When the job is finished, it will disappear from the squeue list.

2. Check the Output Files

After the job completes, Slurm creates output and error files in the same directory. The %A in the script's filename is automatically replaced with the Job ID.

  • hello-7534798.out: Contains the standard output from your script.

  • hello-7534798.err: Contains any error messages. If this file is empty, your job likely ran without errors.

You can view these files to see the results of your job.

[test_user@login-0101 non_mpi]$ sbatch non_mpi.slurm
Submitted batch job 7534798
[test_user@login-0101 non_mpi]$ squeue --me
             JOBID PARTITION     NAME     USER ST       TIME  NODES NODELIST(REASON)
           7534798   sandbox  example  test_user PD       0:00      1 (None)
[test_user@login-0101 non_mpi]$ sleep 8

Once the job is submitted we obtain a job ID number.  This is a unique number for your job allowing for you and administrators of Koa to identify the specific job in the case of troubleshooting or exploration of actual resource usage.  As you can seen our progression, the output of squeue for the users job start in a state (ST) of PD (Pending) and when we return after waiting 8 seconds, and check again, the job is no longer listed.  this signals to us the job is no longer pending or running and has completed either is success or with an error.  Note, if the example was a longer running job, we could see the job enter a state of R (Running).  We conclude the example submission by checking the output using the cat command and see that we did infcat get some output printed to the hello-7534810.out file.
